# CLAUDE.md

Памятка для Claude Code по этому репозиторию. README.md описывает продукт для человека; здесь — то, что
нужно знать, чтобы менять код и не ломать установленное приложение.

## Что это

«Прописи Бори» (`ru.tsakunov.pravka`) — личное Android-приложение Саши для домашнего английского с сыном
Борей (7 лет, 2 класс). Шесть вкладок: Гармошка (письмо на время), Слова (карточки, училка, контроша с
микрофоном, рассказ), Грамматика (тренажёр по фото правила), Домашка (проверка фото тетради), Текст
(чтение с микрофоном и переводом), Статистика (всё вместе за неделю, месяц, всё время). Плюс «Вся
домашка»: пакет фото раскладывается по вкладкам, при желании через Message Batches вдвое дешевле.
Весь ИИ — Claude через Messages API с принудительным вызовом инструмента и strict-схемой.

Пользователей двое: папа и ребёнок. Интерфейс на русском, кавычки «ёлочки», без эмодзи, крупные кнопки и
цифры, никаких длинных текстов на экране ребёнка. Тон подписей дружелюбный, без сюсюканья.

## Сборка и проверка

- Kotlin 2.3, AGP 8.13, Gradle 8.14 (wrapper), compileSdk 36, minSdk 26, JDK 17+ (локально работает 21).
- В этом окружении нужен `ANDROID_HOME=/opt/android-sdk`. Эмулятора нет, запускать приложение негде:
  проверка — компиляция, юнит-тесты и внимательное чтение. Для рискованных изменений полезно попросить
  независимое ревью отдельным агентом.

```bash
ANDROID_HOME=/opt/android-sdk ./gradlew --no-daemon -q :app:compileReleaseKotlin        # быстрая проверка
ANDROID_HOME=/opt/android-sdk ./gradlew --no-daemon -q :app:testDebugUnitTest :app:assembleRelease
```

- Тесты: JUnit 4 в `app/src/test`, чистая JVM. `org.json` подключён как testImplementation, поэтому
  JSON-модели тестируются напрямую. Отчёты в `app/build/test-results/testDebugUnitTest/*.xml`.
- Перед пушем: компиляция, все тесты зелёные, релизная сборка собирается. Пуш с падающим тестом ломает CI.

## Релизы и обновление

- Каждый пуш в `main` или `claude/**` запускает `.github/workflows/build.yml`: `assembleRelease` →
  GitHub Release с тегом `build-N`, файл `pravka-<versionName>-buildN.apk`.
- `versionCode` = `GITHUB_RUN_NUMBER` (локально 1), `BuildConfig.BUILD_NUMBER` тот же номер (локально 0).
  Приложение само сравнивает его с последним релизом (`api/Updater.kt`) и предлагает обновиться.
- Debug и release подписаны одним ключом `keystore/pravka.jks` (алиас `pravka`, пароль
  `pravka-borya-2026`), он в репозитории намеренно: иначе обновление не встанет поверх старой версии.
  Не менять ключ, алиас, пароль и applicationId.
- Готовый APK удобно скачать из Releases и проверить `aapt2 dump badging` (versionCode должен равняться N).

## Правила, которые легко нарушить

### Room
- Любое изменение сущности: поднять `version` в `AppDatabase`, добавить `AutoMigration(from, to)`,
  собрать проект, закоммитить новый `app/schemas/.../N.json`. Старые json не трогать.
- Новые колонки только nullable или с `@ColumnInfo(defaultValue = ...)`, иначе автомиграция не соберётся.
- Сложные структуры (результат проверки, набор правил, разбор чтения, части разбора домашки) хранятся
  JSON-строкой рядом с моделью `toJson`/`fromJson` в `domain/`. Разбор всегда терпимый (`opt*`, `runCatching`).
- Удаление родителя чистит зависимые записи явно в Repository (чтения текста, рассказы), не полагаясь на UI.

### Claude API
- Модель по умолчанию `claude-opus-5` (`Settings`). Все вызовы через `ClaudeApi.callTool` с `strict: true`,
  `tool_choice = {type: tool}`; при 400 про `tool_choice` один повтор с `auto`; beta `fallbacks` пробуем
  и при 400 отключаем. В пакетах `fallbacks` не отправляем.
- Каждый разборщик (`ClaudeVocabParser`, `ClaudeHomework`, `ClaudeGrammar`, `ClaudeReading`) умеет
  `request(images)` без отправки и `fromToolInput(json)` без сети: так один и тот же код работает и в
  прямом вызове, и в пакете. Новые разборщики делать по этому образцу.
- Схемы инструментов: `objectSchema` требует все поля (`required` = все ключи, `additionalProperties: false`);
  необязательное выражается пустой строкой или пустым массивом, не отсутствием ключа.
- Судья контроши: `maxTokens` 4000, `effort = "low"`, таймаут 25 с. Маленький `max_tokens` обрывает ответ.
- Фото кодируются на `Dispatchers.IO`; `BitmapFactory.decodeStream` с `inJustDecodeBounds` возвращает null
  по контракту, проверять поток, а не результат.
- Тексты ошибок для пользователя по-русски, из `describeError`; сырые ответы сервера не показывать.

### Compose
- Экран = фазы (`sealed interface`). Действие, которое пишет в базу, переключает фазу синхронно до
  `launch`, чтобы второй тап не записал дубликат (Practice, Reading, Grammar так и сделаны).
- Долгая работа, результат которой нельзя потерять (вердикт модели, запись чтения), идёт в
  `viewModelScope` (`async` + `await` с экрана), а не в `rememberCoroutineScope`.
- Flow по идентификатору берётся через `vm.cached(key)`, иначе `collectAsStateWithLifecycle`
  переподписывается на каждую перекомпозицию.
- Пока Room не ответил, экран деталей пустой; «не найдено» показывать только для реально удалённой записи.
- Снекбар через `vm.showToast`. `keepScreenOn` живёт в `PravkaRoot` (по маршруту), не в экране.
- Разрешение CAMERA намеренно не запрашивается: `TakePicture` через FileProvider (`cache-path camera/`)
  его не требует. Микрофон: `RECORD_AUDIO` запрашивается на месте.
- Нижняя панель на шести вкладках: подписи у всех только при ширине ≥ 480 dp.
- `PravkaColors.Page` прозрачный: настоящий фон с узором рисует `EnglishBackground` в `PravkaRoot`, экраны и
  шапки его не перекрывают. Непрозрачный цвет листа — `PravkaColors.PageBase`.

### Речь
- `SpeechInput` держит один `SpeechRecognizer` и делает `cancel()` между репликами; пересоздание даёт
  `ERROR_RECOGNIZER_BUSY`. Один язык на сеанс: чтение с переводом идёт шагами en-US → ru-RU.
  `finish()` = `stopListening()` (результат придёт), `stop()` = `cancel()` (без результата).
- Контроша работает по кнопке: нажал — слушаем, нажал ещё раз — `finish()`. Не возвращать автозапуск
  микрофона: он ловит разговоры вокруг, а ребёнок не успевает собраться. Второй режим без микрофона
  (`Settings.quizMic = false`): папа жмёт «верно» / «не верно», фазы те же (Prompt → Correct/Wrong).
- `SpeechInput.checkEnglish` / `downloadEnglish` (Android 13+) — проверка и загрузка английской модели через
  отдельный экземпляр распознавателя; рабочий экземпляр не трогать.
- Наушники: при внешнем входе (Bluetooth, гарнитура) на Android 13+ `MicFeeder` пишет встроенный микрофон в
  трубу и отдаёт её через `EXTRA_AUDIO_SOURCE`. Если труба не читается 1,5 с, ставим `Settings.micPipeBroken`
  и больше не пробуем. Создавать `SpeechInput` только через `vm.speechInput(context)`, чтобы настройки дошли.
- `EXTRA_BIASING_STRINGS` (слова урока, слова предложения) движок может игнорировать; это подсказка, не фильтр.
- Колбэки распознавания сравнивают текущую фазу с той, при которой стартовали (`phase != m`), иначе
  устаревший результат двигает сценарий.
- `Speaker` (TTS) откладывает фразу до готовности движка; перед озвучкой выключать микрофон.

### Продуктовые договорённости
- Буквы считаются вместе с артиклем и «to»: `a hen` = 4, `to plant` = 7. Слова хранятся как напечатаны.
- Единственная метрика письма: секунды на букву. Рекорд только для слов от 3 букв.
- Повторы одного слова группируются `normalizeWord` (без артикля, ё = е), так бумажные и новые попытки сходятся.
- Бумажные результаты в `Seed.kt`: правка данных = `VERSION + 1`, идентификаторы стабильны, посев REPLACE.
- Скорость чтения считается по чистому времени чтения (`readMs`), чтобы микрофон и секундомер были сравнимы.
- Статистика (`domain/Overview.kt`) считает всё из событий с временем: попытки письма, контроши, чтения,
  `activity_log` (обучалка, училка, тренажёр), проверки домашки. Новое занятие → писать в журнал.

## Стиль

- Kotlin с завершающими запятыми, короткие функции, `remember(key)` вместо ручного сброса состояния.
- Комментарии по-русски и о «почему», не о «что». Названия классов и функций по-английски.
- Подписи в интерфейсе: без канцелярита, без восклицаний в каждой строке, ребёнку понятно с первого раза.
- Коммиты: заголовок по-английски в повелительном наклонении, тело списком изменений.
